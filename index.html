作業机と書庫の物語

HTMLからGitHubまで、G'sの最初の1か月の道のり

これは、G's（DEV32期）に入学した牧子さんが、最初の1か月で歩いてきた道のりを、ひとつの物語にしたものです。カッコの中は、物語の中のものが、実際には何にあたるかを示しています。スクロールすると、章ごとの絵が動きます。

第一章　第1回 HTML・CSS

家を建てる

はじまりは、一軒の家を建てることでした。

まず、柱と壁で骨組みを立てます。ここが見出し、ここが文章、ここが写真の場所。どの部屋に何を置くかを決めていく作業です（HTML）。骨組みだけの家は、まだ白くて味気ありません。そこに、壁の色を塗り、床を張り、窓の大きさをそろえて、内装をととのえていきます（CSS）。

ところが、設計図を開いた牧子さんは、まず記号の森で迷子になりました。< と >、{ と }、( と )、それに「;」や「:」。どれも見たことはあるのに、ここでは何を意味しているのかが、まったくわかりません。そこで、記号を一つずつ日本語に置きかえる早見表を作りました。< > は「部屋の名札のかっこ」、{ } は「ここからここまでが、ひとまとまり」。森の木に、一本ずつ名札をつけていくような作業でした。

設計図の書き出しにも、ふしぎな呪文がありました。空っぽの紙に「!」を打って Tab を押すと、家の土台が一気に現れる（! ＋ Tab）。ところが、同じ「!」は、メモ用紙の印（<!-- -->）にも、家の宣言（<!DOCTYPE html>）にも出てきます。どれがどれだかわからなくなり、宣言の頭の「<」を1つ落としてしまったこともありました。

内装を整えるときにも、つまずきがありました。内装の紙には「この名前の部屋は、こう塗る」と書きます（class、id）。でも、骨組みの側の名前と、1文字でもちがうと、ペンキはどこにも塗られません。名前を1文字ずつ見くらべて、やっと色がつく。部屋を横に並べる道具（Flexbox）や、角を丸くするやすり（border-radius）も、こうして一つずつ手になじませていきました。

最初に建てたのは、お手本どおりの「チーズアカデミー」の家でした。見出しの閉じ忘れで、下の階まで全部大きくなってしまったり、内装の指示を、うっかりメモ用紙（コメント）の中に書いてしまったり。それでも一つずつ直して、家は建ちました。そのあと牧子さんは、同じ骨組みを使って、内装と家具を入れかえ、「イノチAI」の家に作り変えました。

第二章　第2回 JavaScript

スイッチをつける

コンピューターのくじ：—
羽田発　ミステリーツアー
？？？
予算を選ぶと、行き先が1秒かけて現れます（fadeIn(1000)）

家は建ちましたが、まだ何も動きません。そこで、スイッチをつけることにしました（JavaScript）。

ボタンを押すと、明かりがつく。押すたびに、何かが起きる。家に「動き」が生まれます。最初につけたスイッチは、おみくじでした。押すと、見えないところでサイコロがふられ（乱数）、出た目によって「大吉」や「吉」に分かれて（if文）、紙に書かれて出てくる（.html）。

課題は、じゃんけんでした。ところが、牧子さんは、ふだんのじゃんけんでも、勝ち負けがこんがらがってしまうことがあります。グーとチョキなら、どちらの勝ち？　あいこのときは何を出す？　頭の中で組み合わせを並べるたびに、迷路が深くなっていきました。正しい組み合わせは、家庭教師（Claude Code）に教えてもらいました。

じゃんけんの家を建てたあと、牧子さんは考えました。前の回で覚えたこと（色、写真、枠）の復習も、もう一度したい。それなら、同じしくみで、ちがう家を建ててみよう。

最初に思いついたのは、マインドフルネスでした。ボタンを押すと、ボディスキャン、数息観、バタフライハグ、完全呼吸……と、9つの実践のどれかが出てくる。けれど、しばらく考えて気づきました。頭がいっぱいのときに、呼吸法を選ぶのは、かえってむずかしい。占いのような形も考えてみましたが、どこかぱっとしません。

そして、ふと浮かんだのがミステリーツアーでした。2万円なら、ソウル、台湾、宮古島。5万円なら、バンコク、シンガポール、ホノルル。10万円なら、ロンドン、シドニー、ロサンゼルス。予算を選ぶと、どこへ行くかがわからないまま、羽田から旅に出る。自分の手（予算）と、コンピューターの手（1〜3のくじ）。じゃんけんと同じしくみで、9つの旅が生まれました。

家庭教師に、まず全力でおしゃれな見本を建ててもらいました。くるくる回るガラガラ、マーライオンやハリウッドの丘の写真、ふわっと現れる切符。見とれるほどの家でした。けれど、よく見ると、まだ習っていない道具がたくさん使われています。「これは難しすぎない？」。そこで、習った道具だけで建てる設計図に作りなおしてもらい、牧子さんは自分の手で一から打っていきました。

自分で打つと、思いもよらないところでつまずきます。手順書の10番目が、何を言っているのかわからない。写真を入れる1行（photo の行）を、どこに書けばいいのかわからない。同じ if の部屋を二重に作ってしまったり、スイッチの最後の「});」を閉じ忘れたり。内装の紙（CSS）の中に、スイッチの命令（JavaScript）がまぎれこんでいたこともありました。

いちばん長く悩んだのは、写真が写らないことでした。img の棚には、たしかに9枚の写真が並んでいます。ところが、よく見ると、それは写真そのものではなく、写真のありかを指す道しるべ（ショートカット）でした。道しるべを額縁に入れても、絵は飾れません。本物の写真を棚に入れなおすと、切符の上に、ソウルの街並みが浮かびました。

切符がふわっと出てくるまでの時間も、自分で決めました。最初の2秒（fadeIn(2000)）は、少し長い。1秒にすると、ちょうどいいドキドキになりました。

ひととおり建て終わってから、牧子さんは、もう一度、同じ家を一から建てなおしてみることにしました。家ごと写して（フォルダのコピー）、今度は見本を見ずに、自分で打つ。2回目は、1回目より、ずっと迷わずに進めました。

そして、建てなおしているうちに、気づいたことがあります。行き先は9つ用意したけれど、コンピューターが出しているのは、いつも1〜3の、たった3つの手。9通りの旅は、予算（3つ）と、くじ（3つ）の組み合わせから生まれていたのです。「要は、そういうことか」。じゃんけんの迷路の出口が、旅の地図の上で見えた瞬間でした。

この家づくりで、牧子さんは一つの習慣を身につけました。家庭教師に「直して」と頼むのではなく、「どうすればいいかな？」と聞くこと。答えをもらうのではなく、自分で直すための道しるべをもらうこと。提出の紙にも、正直にこう書きました。家庭教師がいたから、心折れずに進めることができた、と。

第三章　第3回 Git・GitHub　4〜5章

書庫の合鍵をつくる

家がいくつか建つと、新しい悩みが出てきます。「どれが最新の設計図だっけ？」「前のほうがよかったのに、もう戻せない」。

そこで登場するのが、記録係のノートと、インターネットの向こうにある大きな書庫です。ノートは、家をどう変えてきたかを、日付と理由といっしょに書きとめてくれます（Git）。書庫は、そのノートと設計図を、なくさないように預かってくれる場所です（GitHub）。牧子さんの作業机は、自分のパソコンです。

書庫に出入りするには、まず名札が必要でした。名前とメールアドレスを書いた名札です（4章　git config）。

次に、合鍵をつくりました（5章　SSHの鍵）。合鍵は2本で1組です。1本は自分の手元にだけ置いておく鍵（秘密鍵）、もう1本は書庫に預けて「この鍵を持っている人は牧子さんです」と覚えてもらうための鍵（公開鍵、.pub）。途中で、手元に置いておくはずの鍵を外に出してしまうハプニングもありましたが、まだ書庫に預ける前だったので、鍵を作り直すだけですみました。

合鍵を書庫に預けて、ドアをたたきます（ssh -T）。はじめての訪問なので、書庫の番人に「この書庫に入って本当にいいですか？」と聞かれました。一度目は、うっかり返事をしそびれて、ドアは閉じたまま。二度目に、はっきり「yes」と答えると、ドアが開いて、こう迎えられました。

「Hi makikonakaba-bit!（ようこそ、牧子さん）」

第四章　第3回 Git・GitHub　6章

箱をひもでつなぐ

書庫の中に、自分専用の空っぽの箱を1つ用意しました（6-1　リポジトリ gs-learn-git）。

それから、作業机を整えました。机の上には、OneDriveという、勝手に別の場所へ荷物を運んでしまう棚があります。そこを避けて、自分の部屋の中に、新しい作業スペースを作りました（gs フォルダ）。

そして、書庫の箱と同じ箱を、作業机の上に置いて、ひもでつなぎました（6-2　git clone）。これで、机の箱と書庫の箱は、いつでも行き来ができるようになりました。

こうして、牧子さんの机の上に、まだ空っぽの箱が1つ置かれました。

第五章　第3回 Git・GitHub　7章

はじめての記録を、書庫に届ける

空っぽの箱に、まず紙を1枚入れました（test.text を作って保存）。名前は、手順書の「test.txt」ではなく「test.text」になりましたが、練習の紙なので、そのまま使うことにしました。

記録係に「机の上で、何か変わったものはある？」とたずねると（git status）、記録係は赤い文字でこう答えました。「まだ私の知らない、新しい紙があります」（Untracked files）。

その紙を、「これを次の記録に入れます」と、記録用のトレーにのせます（git add）。もう一度たずねると、今度は緑の文字で「記録する準備ができたものがあります」（Changes to be committed）。

そして、ノートに一言そえて記録しました（git commit -m）。一言は「test.textを追加」。記録には「1a7de7b」という番号がつき、「root-commit」、つまりこの箱のいちばん最初の記録として、ノートの1ページ目に書きこまれました。

最後に、ひもを引きます（git push origin main）。荷物が数えられ、包まれ、送られていきました（Writing objects: 100%）。返ってきた知らせは「main -> main」。机の main の記録が、書庫の main の棚に届いたという合図です。

確かめに行こうとして、牧子さんは一度、ブラウザで自分の机の上をのぞいてしまいました（自分のパソコンの中の住所）。アドレスを「https://github.com/」で始まる書庫の住所に変えると、そこには、さっきの紙と「test.textを追加」の一言が、「3分前」という日付とともに、ちゃんと並んでいました。

机の上で書いた1枚の紙が、ひもを伝って、インターネットの向こうの書庫に届いた瞬間でした。

第六章　第3回 Git・GitHub　7章〜Pages

説明書を入れ、家を展示室に出す

練習の箱に、説明書を1枚入れることにしました（README.md）。見出しの「#」、箇条書きの「-」。書庫に届けば、記号が消えて、読みやすい説明書になるはずです。

ところが、記録係に聞いたあと、すぐにひもを引いてしまいました。書庫からの返事は「Everything up-to-date（届けるものは、もう全部届いています）」。紙をトレーにものせず、ノートにも書いていなかったので、運ぶものがなかったのです。もう一度トレーにのせようとすると、今度はGitが、長い英語の使い方の説明書を出してきました。書き方が少しちがっていた合図です。

そこで牧子さんは、1つずつ確かめることにしました。半角で「git add README.md」。記録係に聞くと、緑の文字。ノートに「READMEを追加」と書いて、ひもを引く。書庫の箱には、「18分前」の紙のとなりに、「たった今」の説明書が並びました。

いよいよ本番です。書庫に、ミステリーツアー専用の新しい箱を用意しました（mystery-tour）。机に持ってくるときは、一度「githubu」と打ちまちがえて、番人に「そんな書庫は知りません」と言われましたが、打ち直すと、空っぽの箱がちゃんと届きました。

次は、家そのものを探す旅でした。ミステリーツアーは、OneDriveの棚の、ずっと奥のほうにしまわれていました。棚の上には、雲に×の札。OneDriveが、荷物をうまく運べずに困っている印です。講義で「この棚には置かないで」と言われていたのは、こういうことでした。

棚の中から、必要な3つだけを選びました。内装の箱（css）、9枚の写真（img）、そして家の本体。家の本体には「index」という新しい名前をつけました。展示室が、最初にお客さんを迎える玄関の名前です。写真の名前も、大文字・小文字まで1つずつ見くらべました。London の L まで、ぴったりそろっていました。写真のあいだにまぎれていた2つの道しるべ（ショートカット）は、書庫には入れないように、そっと取りのぞきました。

3つまとめてトレーへ（git add .）。最初は「.」を忘れて、Gitに「もしかして git add . のこと？」と聞き返されました。ノートには「羽田発ミステリーツアーを追加」。ひもを引くと、今度は「github.com が見つかりません」。インターネットの道が、一瞬ふさがっていたのです。記録はノートに残っているので、あわてずにもう一度ひもを引くと、家は書庫に届きました。

最後に、書庫の設定で、家を展示室に出しました（GitHub Pages：Settings ＞ Pages ＞ main ＞ Save）。1、2分待つと、展示室の住所ができあがりました。

https://makikonakaba-bit.github.io/mystery-tour/

自分の机の上でしか開けなかった家が、今は、誰でも、どこからでも訪ねてこられる場所に建っています。予算のボタンを押すと、切符がふわっと現れて、マーライオンも、ビッグ・ベンも、ハリウッドの丘も、ちゃんと迎えてくれました。

ふと、牧子さんは思いました。イノチAIを出しているNetlifyとは、何がちがうのだろう。答えは、展示室の裏に、作業部屋があるかどうかでした。GitHub Pagesは、作品を飾るための展示室。Netlifyは、展示室の裏に作業部屋があって、AIとやりとりするための秘密の鍵を、お客さんから見えないところにしまっておけます。イノチAIに作業部屋が必要な理由も、いっしょに見えてきました。

第七章　11月11日 リッチバージョン

二つ目の家と、金色の切符

行き先のくじ r と、アップグレードのくじ r2（5回に1回）
羽田発　ミステリーツアー（リッチ）
？？？

翌日、牧子さんは学校からの知らせを読みなおしました。提出の欄は、課題ごとに分かれています。「じゃんけんアプリ」の欄と、「じゃんけんアプリ リッチver.」の欄。もし今の家をそのまま改装したら、前の課題の欄から訪ねてきた人も、改装後の家を見ることになってしまいます。

そこで、家をもう一軒、建てることにしました。書庫に新しい空の箱を用意して（mystery-tour-rich）、机に持ってくる（git clone）。番人からは「空っぽの箱ですよ」とひとこと（warning: empty repository）。それは、ちゃんと届いたしるしでした。

今度は、棚を探しまわる必要はありません。となりの箱から、内装と写真と家の本体を、まとめて写すだけです（cp -r）。一度目は「- r」と空白を入れ、箱の名前から「-」を落として、「そんな箱はありません」と言われました。打つより貼るほうが確か。長い呪文は、写して貼ることにしました。

トレーにのせて、ノートに「ミステリーツアーをコピー」、ひもを引いて、展示室へ。二度目の道のりは、一度目よりずっと短く感じられました。

さて、改装です。牧子さんは考えました。もう少し、ギャンブルのドキドキがほしい。たどりついたのは、とてもシンプルな仕掛けでした。行き先のくじとは別に、もう1枚、小さなくじを引く。10人に1人だけ、切符に「✈ ビジネスクラスにアップグレード」と書きこまれる。

切符に、書きこむための空欄を1つ足しました（<p id="upgrade">）。スイッチには、新しいくじ（r2）を。行き先のくじ（r）を使い回すと、当たるのがいつも宮古島になってしまうからです。2万円で試すと、台湾の切符に、ちゃんと文字が現れました。

ところが、5万円と10万円にも同じ仕掛けを写したとたん、家じゅうのスイッチが、どれも動かなくなりました。原因は、5万円の部屋のかっこの閉じ忘れ（}）。たった1つの扉が開けっぱなしなだけで、家全体が読めなくなる。それがプログラムの世界でした。もう1つ、空欄を消す命令から「#」が抜けていました。宛先のない手紙は、どこにも届きません。

金色にしようと内装の紙（CSS）に書き足すと、今度は色が変わりません。ここでも、すぐ上のフッターの部屋の扉が、閉じられていませんでした。金色の指示は、フッターの部屋の中に迷いこんでいたのです。

いちばん不思議だったのは、切符が勝手に消えることでした。何もしていないのに、写真がふっと消える。調べてみると、スイッチの外に、昔の命令が3行残っていました。家を開くたびに「消す、出す、消す、出す……」と、切符の前に順番待ちの列を作っていたのです。その列の途中でボタンを押すと、新しい切符が出たあとに、残っていた「消す」の番が回ってくる。3行を消すと、切符はもう、勝手に消えなくなりました。

机の上では、金色の切符が出ます。けれど、展示室に行くと、何も変わっていません。理由は2つありました。1つめ、ノートに記録して、ひもを引くまでは、展示室の家は変わらないこと。2つめ、お客さんのブラウザが、前に見た内装の紙を、しばらく覚えていること。牧子さんは、くじの確率を「5回に1回」に変えたあと、ひもを引くのを一度忘れて、「そうでした💦」と笑いました。

ひもを引いて、少し待って、強く読み込み直す（Ctrl + Shift + R）。展示室のバンコクの切符に、金色の太い文字が浮かびました。

✈ おめでとうございます！ビジネスクラスにアップグレード

机で直す。ノートに書く。ひもを引く。展示室で確かめる。この4つの手順が、この日、牧子さんの手になじみはじめました。

家を改装して、学校に届ける

ここまでで、家を建て、記録し、書庫に届け、展示室に出すまでの道を、牧子さんは全部、自分の手で通りました（✓）。

物語の中で実際の操作
机の箱に、紙を1枚入れるファイルを作って保存する✓
「これを記録に入れます」と、紙をトレーにのせるステージに入れる（git add）✓
ノートに、日付と「何をしたか」を書いて、記録するコミットする（git commit）✓
ひもを引いて、書庫の箱にも同じものを届けるプッシュする（git push）✓
書庫の箱に、家の説明書を入れるREADME.md（練習の箱で）✓
書庫の箱から、家を展示室に出すGitHub Pagesで公開する✓
二軒目の家を建てる（となりの箱から写す）新しいリポジトリに clone して、cp -r でコピー✓
家を改装する。改装のたびに、ノートに記録して書庫に届けるアップグレード機能　機能ごとに add → commit → push✓
2つの家の箱に、説明書を入れるREADME.md を書く（rich と mystery-tour）これから

これから先は、同じ箱の中で、家を少しずつ改装していきます。改装のたびにノートに1行ずつ記録が増え、ひもを引くたびに、展示室の家も新しくなっていきます。
